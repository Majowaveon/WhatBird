# 美术与策划关卡编辑指南

正式关卡已生成为 Godot 原生可编辑场景。场景生成时按要求未执行游戏测试；后续前景水调整已补充水面渲染检查并重跑集成与跳跃检查，不代表完整关卡连续通关。

## 从这里开始

1. 用 Godot 4.5.1 导入本目录 `project.godot`。
2. 在文件系统面板打开 `scenes/rooms/w0l1.tscn`。共有 20 个房间：w0l1～w0l6、w1l1～w1l7、w2l1～w2l7。
3. 在二维视图修改，Ctrl+S 保存。
4. F6 单独预览当前房间；F5 从菜单运行完整游戏。

总地图是 `scenes/maps/testyxh1.tscn`，引用这些房间场景。通常编辑房间文件，不要把总地图中的房间设为“本地化”来复制一份；否则会与原房间文件分离。

## 房间结构

- `Terrain`：实体地形，每个 `TileMap_*` 下都有真正的 `TileMapLayer`。
- `Background` / `Foreground`：背景和前景瓦片层。背景根节点保留各房间原有深度，用来衔接相邻场景；只有底层泥土会在需要时高于背景。不要把底层泥土调回背景之后，否则 w1l1 等房间的地形会被背景盖住。20 个房间都已检查过这一层级关系。
- `Actors`：门、按钮、木块、弹簧、触发区、道具和提示。
- `Decoration`：特殊装饰（可选）；前景反射水由房间根节点的参数控制。
- `PlayerStart`：本房间单独预览的出生位置。

部分房间没有某一种分类，这是正常的。总地图根部另有 `PlayerStart`，控制完整流程的初始出生点。

## 画地形

选中 `Terrain/TileMap_房间名/PaperTileLayer_*`，底部会显示 Godot 的 TileMap 绘制面板。选择图集后用画笔、直线、矩形、橡皮等工具编辑。不是 MeshInstance2D 的只读图像。

TileSet 位于 `resources/tilesets/*.tres`，已带原图集和碰撞多边形。选中瓦片层的 `Tile Set` 资源可进入 TileSet 编辑器，调整单格碰撞。`TileMapLayer` 的 `Collision Enabled` 可开关整层碰撞；装饰图集没有碰撞多边形。

TileSet 可能被多个图层/房间共享。若只想改当前层的碰撞或图集定义，先对资源使用“唯一化”或另存为新 `.tres` 再修改。只画/擦地图格子不会改别的房间。

## 移动机关和改碰撞

选中 `Actors` 下的机关根节点即可拖动整个机关。节点名称沿用原关卡标签，例如 `BP_Door_w0l4_1`、`BP_Button_w0l4`。

- 改外观位置/缩放：调整 `RenderComponent` 或其中的 `AnimatedSprite2D`。
- 改实体碰撞：找到 `Box/StaticBody2D/CollisionShape2D`（Godot 自动命名可能带编号），修改矩形形状尺寸。
- 改触发范围：找到 `TriggerBoxComponent/Area2D/CollisionShape2D`，或水区根部 `Area2D` 的形状。
- 复制机关后最好清空其 `Object Id`；加载时会为新节点使用唯一路径标识。节点名称可以改，门按钮关联用 `NodePath` 指向实际节点。
- 不要删除机关根节点的 `world_object.gd` 脚本，它负责行为。保留场景内的 Area2D、StaticBody2D 和 CollisionShape2D，运行时会直接绑定它们，不重新生成覆盖。

## 检查器中的策划参数

| 参数 | 用途 |
| --- | --- |
| `Kind` | 机关行为类别，复制同类机关时通常不用改 |
| `Linked Buttons` | 门等待的按钮节点路径，全部触发才开门 |
| `Linked Doors` | 按钮直接开门的路径，保留原关卡旧关联行为 |
| `Target Room` | 切房间触发器的目标标签，例如 `SubLevel_w0l2` |
| `Unlock Form` | 解锁道具的鸟形态 |
| `Pickup Amount` | 增加的变身次数 |
| `Launch Speed` | 弹簧或上升通道力度 |
| `Break Delay` | 木块隐藏后多久关闭实体碰撞 |
| `Spring Animation` | 弹簧触发时的 SpriteFrames |
| `Pressed Animation` | 按钮触发时的 SpriteFrames |
| `Randomize Wood` / `Wood Variants` | 是否从木块外观集合随机选择 |

注意：原版的门在 `Linked Buttons` 为空时会直接打开；新门请关联按钮。若希望多按钮 AND 条件生效，不要同时把同一门放进某一个按钮的 `Linked Doors`，因为后者会直接开门。

动画资源位于 `resources/animations/*.tres`。美术可以编辑 `AnimatedSprite2D` 的 `Sprite Frames`，或将新的 SpriteFrames 拖进节点。想固定木块外观时关闭 `Randomize Wood`，避免运行时被随机外观覆盖。

## 房间镜头和变身额度

选中房间根节点：

- `Room Tag`：房间标识，切房间机关的 Target Room 要与它对应。
- `Transform Limit`：初始变身次数，-1 为无限。
- `Camera Bounds`：房间本地坐标中的镜头矩形。二维视图绿色线框表示范围。扩展地图时也需要调整它。
- `Preview Form`：F6 独立房间预览时的初始形态。
- `Show Camera Bounds`：仅编辑器中显示线框，不进入游戏画面。

F6 房间预览会临时解锁全部形态，方便调关卡；仍使用该房间变身次数。预览运行在单个房间中，跳到未加载的其他房间不会有完整主流程效果。检查跨房间连接请用 F5 或打开总地图 F6。

## 前景反射水

选中房间根节点，在 `Foreground Water` 分组调整：

- `Foreground Water Enabled`：本房间是否显示前景反射水。默认关闭；有底部水草的房间才开启。
- `Foreground Waterline`：水线离屏幕顶部的比例，数值越大水面越低。当前水草房间统一设为 `0.78`，覆盖其下方直到屏幕底部。

水带横向铺满屏幕，不再按旧三维平面做梯形投影。倒影按水线等比例上下翻转，超出底边直接裁掉，不把整个上半屏压缩进水带。波纹和高光使用世界坐标，随镜头平移与缩放，不固定贴在屏幕上。水草画在水面之上，换房时水面淡入淡出，窗口缩放不改变水线的屏幕比例。

前景草保持场景设定的透明度，切房时不淡入淡出，也不隐藏相邻房间。前景瓦片按所属房间的 `Camera Bounds` 裁剪，避免倒置草图越界挡住邻房（例如绿头鸭教学房间 w1l1）。横向相邻、使用同一套美术的房间交替左右镜像；512 像素宽的装饰图用 `Scale.x = ±0.9375` 精确覆盖 480 像素房间，并对齐高度。w0l4、w0l6 使用与邻房一致的水草构图。

当前开启 w0l1～w0l6、w1l5～w1l7；w1l2 的草在顶部，w1l1/w1l3/w1l4 无底部前景草，w2 组为干燥地表，均关闭。这里控制的只是前景装饰，原有可游泳水池的瓦片、触发区与死亡规则不变。旧 `BP_WaterPlane` 定位节点不再驱动水面。

## 改房间之间的位置

打开 `scenes/maps/testyxh1.tscn`，移动房间实例根节点。房间内地形、机关、检查点和相机范围会一起移动。修改边界或相邻房间的位置后，需要同步调整连接触发器和出生/检查点位置。

需要无缝拼接的背景和水草使用普通二维变换，不设置 `Perspective Depth` 元数据；否则运行时按相机重新投影会破坏接缝。调整房间宽度时，同步调整装饰层宽度和中心位置；相邻房间应使用同一构图、相同高度和相反的横向缩放。

## 与旧 JSON 的关系

游戏默认加载 `scenes/maps/testyxh1.tscn`，不会在启动时重新读取 JSON 来覆盖房间里的坐标、瓦片、碰撞和机关参数。`data/world.json`、`paper2d.json` 仍保留为原始转换输入；玩家动画等公共资源也继续使用其中部分索引。

`--data-driven` 启动参数可显式切回旧数据驱动路径，用于开发对照，不是正常关卡编辑流程。

**不要在美术/策划已经修改场景后随手重新生成。** 转换命令默认发现总地图已存在就拒绝覆盖；`--overwrite` 会用原数据重建房间、图集与动画，覆盖场景编辑。重生成前应先提交或备份场景和资源。

生成命令（程序使用）：

```sh
godot --headless --path godot --script res://tools/bake_editable_map.gd -- --overwrite
```

完整连续通关仍未执行。前景水调整后的集成、跳跃与水面检查范围及运行命令见 `README.md` 的验证章节。

# 啥鸟?! / WhatB?! — Godot 移植版

基于原 Unreal Engine 5.7 工程迁移的 Godot 4.5.1 独立实现。旧 UE 工程、提取工具和解析缓存已归档移出工作区，恢复方式见 [UE 工程归档](../Docs/UE工程归档.md)。Godot 运行和关卡编辑不依赖 Unreal、PaperZD、MCP 或 .NET。

当前正式关卡已迁移为可编辑 `.tscn` + `TileMapLayer`，默认运行加载场景。美术/策划请先看 [关卡编辑指南](关卡编辑指南.md)。场景迁移时未运行测试；后续前景水调整已重跑集成与跳跃检查，并补充水面渲染检查，具体范围见下文。

## 运行

在 Godot 4.5.1 或兼容的 Godot 4.x 版本中导入本目录 `project.godot`，按 F6/F5 运行主场景 `scenes/main.tscn`。首次打开会导入纹理、字体和音频。

命令行：

```sh
godot --path godot
```

从仓库根目录运行上述命令；进入本目录后可用 `godot --path .`。Windows 下可在仓库根目录双击 `play.bat`（首次克隆会先自动导入资源），命令行 `play.bat --play` 跳过菜单直接进入正式关卡，用于诊断。发布预设是 `Windows Desktop`，默认输出 `build/windows/WhatB.exe`，包含内嵌资源包，可独立运行。

## 操作

| 操作 | 按键 |
| --- | --- |
| 移动 | A / D 或左右方向键 |
| 跳跃 | W / 上方向键 / 空格；短按低跳，长按高跳，松开收住上升 |
| 夜鹭滑翔 | 空中再次按住跳跃键，松开结束（与长按跳高相互独立） |
| 啄木鸟啄击 | E；空中按跳跃也会触发当前形态技能 |
| 变身 | 1 夜鹭、2 绿头鸭、3 企鹅、4 啄木鸟 |
| 检查点重试 | R |
| 暂停 / 继续 | Esc |
| 形态选择 | 可点击左上角头像展开已解锁形态 |

变身须先解锁，房间次数为零时不能切换；换回夜鹭也消耗次数。检查点保留当时形态，重试恢复检查点位置和形态。正式原关卡没有企鹅解锁点，企鹅能力与动画已实现，但未向主流程擅自增加关卡或道具。

`data/world.json` 保留 10 个原地图路径中的 558 个对象；运行入口使用原菜单实际引用的 `TestYxh1`。其余测试/音频/三维样例地图的数据保留，不宣称已将原工程的 Landscape、HLOD、天空等编辑器样例完整重建为 Godot 三维地图。

## 代码与数据

- `scripts/main.gd`：菜单、输入和生命周期。
- `scripts/world.gd`：正式地图、检查点、房间切换、机关分发。
- `scripts/player.gd`：四形态 CharacterBody2D 控制器。
- `scripts/world_object.gd`：原 Actor 的组件、碰撞、可视和机关状态。
- `scripts/paper_assets.gd`：原图集、帧序列、轴心及像素/单位换算。
- `scripts/tile_map.gd`：批量瓦片绘制和原始碰撞轮廓。
- `scripts/ui.gd` / `audio.gd`：界面与音频。
- `data/world.json` / `paper2d.json`：可追溯的转换数据。
- `data/blueprint_spec.json`：蓝图字节码、参数及行为证据。

当前正式地图入口是 `scenes/maps/testyxh1.tscn`，它引用 `scenes/rooms/` 中的 20 个房间场景。房间使用原生 `TileMapLayer`，外部 TileSet 在 `resources/tilesets/`，可编辑动画在 `resources/animations/`。场景保存的坐标、瓦片、碰撞形状和机关导出参数是运行时依据，JSON 不会在启动时覆盖这些编辑。

F6 支持房间独立预览，F5 保留完整菜单流程。生成工具 `tools/bake_editable_map.gd` 仅用于重新从原转换数据导入，不要在场景修改后无备份使用 `--overwrite`。旧 JSON 网格渲染路径保留为 `--data-driven` 显式回退。

## 验证

可编辑场景生成时未运行测试。后续前景水调整已在原生场景路径重跑：108 项集成、38 项跳跃和 107 项水面检查通过；水面检查覆盖 20 房间开关、缩放、切房间、F6 单房预览、草层遮挡及动态高光，并在真实 GL Compatibility 窗口执行像素读取。后续 7 项水面投影检查验证等比例倒影、波纹及高光的镜头跟随、平移缩放时的水带对齐；27 项前景检查验证 20 房间前景隔离、快速切换与重试，以及绿头鸭水池不再被邻房草遮挡；61 项地形检查逐房验证背景位于所有地形层之后，覆盖全部 20 个房间。另查看了 1280×720 与 1024×576 渲染截图。这些检查不等于完整通关，旧路线脚本的覆盖边界仍如下文所述。

从仓库根目录运行：

```sh
python tools/verify_godot.py --godot godot
godot --path godot --script res://tests/water_regression.gd -- --render
godot --path godot --script res://tests/water_projection.gd
godot --path godot --script res://tests/foreground_regression.gd -- --render
```

后三条需要真实渲染窗口，不能用 `--headless` 代替像素读取。`water_regression.gd` 和 `foreground_regression.gd` 只查逻辑时可省略 `-- --render` 并加 `--headless`；`water_projection.gd` 必须使用真实渲染。

`tests/verification.json` 记录 108 项通过的集成检查，包括实际出生点落地、移动/跳跃、四形态参数、解锁/次数、门按钮引用、攻击、重生、全部房间配置及通关重开。`tests/jump_verification.json` 记录 38 项跳跃回归：高度随按住时长增长且封顶、松开截断、碰顶取消、不与滑翔叠加、不剪弹簧，以及长按直接越过教程第一根木柱。

`tests/campaign_playtest.json` 的 17 项物理目标全部通过：从原出生点经真实输入到第二房间；两个明确传送设置的隔离起点分别验证鸭子拾取/变身/入水/出水/按钮开门/跨房间，以及啄木鸟拾取/变身/破坏/开门/进入下一房间。报告保留两次早期寻路超时，后续目标均已通过。

完整 20 房间连续通关仍未执行，因此该路线报告的 `full_campaign_completed` 和顶层 `passed` 仍为 false，运行命令按设计返回 1。这是诚实的验收边界，不能把隔离诊断或直接调用机关的集成测试混称为人工完整通关。

## 迁移差异

详见 `../Docs/Godot蓝图行为核对.md`。

- 修复原 C++ 鸭子进出水条件提前返回、切形态环境参数遗留及重叠水域布尔标记问题。
- 弹簧按编辑器设计意图恢复弹跳；原保存的运行字节码与编辑器节点不一致。
- 木块保留 1 秒延迟关闭碰撞，重试会使旧延时回调失效，避免旧计时器破坏重置后的机关。
- 检查点额外保存房间以恢复镜头；原蓝图只显式保存位置与形态。
- 前景水使用屏幕下部的横向二维水带；各房间背景保留原有深度以维持相邻场景的连续衔接；仅将原本会被背景盖住的底层泥土提高到背景之上，避免 w1l1/w1l5 等房间的地形消失，仅在有底部水草的房间启用，水草覆盖在水面之上；房间根节点可调开关及水线高度。BackBufferCopy 截取场景，以水线为轴等比例上下镜像，超出水带的部分裁掉，不压缩倒影。波纹和高光固定在世界坐标中，随镜头平移和缩放，并叠加渐暗效果。已移除旧三维平面的梯形投影；这仍是屏幕空间近似，不是 Substrate 的物理反射、折射与光照。原有可游泳水池与触发区不变。Niagara GPU 粒子或后期处理也未逐像素复刻。
- 音乐/音效使用原始波形；MetaSound 的随机、混音和包络以 Godot 音频重建，不是采样级等价转换。
- 角色使用 Godot 2D 物理；原始主要数值已移植，但跨引擎接触、台阶和摩擦手感仍需实际游玩校准。
- 企鹅滑行动画按实际身体底部下移 10 像素贴地。冰面采用独立加速/刹车参数，松键后保持惯性，反向输入先减速。冰面滑行起跳后保持起跳水平速度与滑行动画，碰墙停止、落地结束腾空保持。这是设计者要求的手感调整，不是 UE 原始参数的等价复刻；正式地图未新增企鹅解锁点。独立测试入口和操作见 [企鹅与雪地测试场景](scenes/tests/README.md)。

素材作者和署名沿用原项目，致谢界面保留原图。本迁移不改变原素材的许可或所有权。
